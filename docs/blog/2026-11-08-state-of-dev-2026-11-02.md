# State of Dev

## Week of 2026-11-02

This week WindowManager finished one implementation program, implemented most of another, and produced three prerelease acceptance bundles to demonstrate that "finished" remains a word with several operational meanings.

FileManager reached real installed-upgrade evidence without promoting an unsigned MSI into a release. Platform put identity and ownership in front of the game service. Game Engine published 0.14.0. MemoryKit improved semantic recall substantially and remained too slow by its own declared standard.

This is inconveniently healthy.

## Shipped Work

### Game Engine And Adventures

Game Engine [published v0.14.0](https://github.com/The-Running-Dev/SubZeroDev.GameEngine/releases/tag/v0.14.0) on November 3. The registry archive matched the recorded digest, contained 363 entries, passed isolated installation and consumer smoke checks, blocked deep `dist/` imports, and refused a duplicate publication.

The release moves runtime session-capture types to the root package surface and adds a host-oriented replay-context helper. Adventures consumed the candidate before publication and then shipped the host and UI sides of session capture: explicit report consent, fault-capture consent, 30-day retention, player and administrator access, download and deletion, and deliberately indistinguishable responses for unknown and unauthorized identifiers. The browser capture work reported 66 passing browser tests; server integration remained CI-dependent where PostgreSQL was required.

### Platform

Platform's G3 game-edge program reached 12 of 13 slices landed. The edge now requires verified handoff assertions, scopes sessions, saves and profiles to the signed-in owner, prevents cross-principal operations, distinguishes credential outcomes, applies header policy by mode, enforces abuse limits before forwarding, and proves Adventures through a pinned composition.

MCP now reaches the game service through the same edge and ownership boundary as HTTP. Seven focused composition tests proved an authenticated player can start and play a session while another player receives the same answer as for an unknown session. Game service also moved to Game Engine 0.14.0 and Service Contract 0.9.0.

The remaining G3 slice is the live deployment and rollback proof. A test route table is useful evidence. It is not a reverse proxy merely because everybody agrees with it.

### WindowManager

The original S1–S23 program is merged. WindowManager now covers panels, plugins, settings, installation, multi-monitor and DPI behavior, icon packs, replacement-shell roles, notification area, desktop and wallpaper, Windows-key commands, system indicators, recovery, and performance budgets.

The second-release S24–S31 implementation also landed: Windows notifications, one shared host/plugin window model, virtual desktops and Task View, live thumbnails, quick settings, a Win+X menu, deeper taskbar behavior, per-monitor wallpaper, desktop file actions, and a themed Alt+Tab switcher. The S31 snapshot reported 431 core tests and 157 end-to-end tests passing, with eight skips.

This is merged implementation, not completed real-machine acceptance. Three GitHub prereleases contain VM acceptance bundles; they are test artifacts, not product releases.

## Meaningful Progress

### FileManager

FileManager delivered the service, durable job admission and recovery, provider boundaries, containment rules, create, rename, native move, permanent delete, recursive copy, and shared browser and Windows mutation surfaces.

S18 then moved beyond merely producing an MSI. Upgrade admission now refuses active or unquiesced work, maintenance state is durable, forced replacement records affected operation identities, interrupted migration blocks startup, and recovery preserves request identity without replaying work.

A fresh Windows Server 2025 VM successfully exercised quiet upgrade, active-job refusal and forced recovery. The standard snapshot reported 1,032 .NET tests and 214 web tests passing. Clean-install, uninstall-retention and data-removal scripts are now bundled for disposable VM use.

S18 still remains `todo`: the CI machine is not an accepted FM-U4 target, no production signing certificate was used, and no FileManager release exists. The installer has reached evidence. It has not reached marketing.

### MemoryKit

MemoryKit improved Qwen 2.5 7B recall from 44/58 to 52/58 and Codex from 57/58 to 58/58. Measured cold p95 fell from 120.1 to 29.2 seconds for the GPU-assisted Qwen profile and from 54.8 to 37.8 seconds for Codex. Native validation reached 18/18 Codex checks and 17/17 Claude Code checks; the merged qualification snapshot reported 410 local tests and 84 live PostgreSQL tests passing, with three skips in each relevant suite.

Both providers still exceed the declared 10-second cold-readiness gate. Follow-up work added phase timings and reusable native catalog metadata, but explicitly did not claim an end-to-end speedup. MemoryKit remains unpublished.

### Runners And Docker-BuildAgent

Runners can now bootstrap a Windows host from one command, installing prerequisites and configuring two isolated native runners by default. The setup preserves working identities on rerun, validates intended repository scope, and provisions the pinned Docker-BuildAgent tool and digest-pinned image. Docker-BuildAgent itself learned to preserve privileged mode, resource limits, tmpfs mounts, stop timeouts and network aliases while replacing a runner container.

The scripts and synthetic evidence are green. Actual registration, concurrent jobs, Docker Desktop acceptance and lifecycle recovery on the 128 GB target machine remain unverified. The open acceptance PR exists precisely because mocked runners are unusually cooperative employees.

## Decisions

- WindowManager tracks hidden windows in the shared model and lets each view decide eligibility. Lifetime identity uses a host generation plus a fingerprint instead of pretending a window handle is a durable identity.
- Platform's game edge owns authentication and principal isolation for both HTTP and MCP. Direct workload access without the edge assertion is refused.
- FileManager upgrades default to refusal when mutations are active. `FORCE=1` is an explicit recovery path with durable identity capture, not permission to forget what was interrupted.
- MemoryKit keeps the 10-second cold p95 readiness gate. Better recall does not convert a 37.8-second cold path into "ready" through editorial enthusiasm.
- Docker-BuildAgent preserves only enumerated replacement settings. Unknown container shape still fails before destructive change.
