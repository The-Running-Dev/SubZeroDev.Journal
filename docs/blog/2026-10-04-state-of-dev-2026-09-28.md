# State of Dev

## Week of 2026-09-28

This week produced 254 merged pull requests across The-Running-Dev.

The more consequential number is one.

AgentKit now expects one `/next` session to build an entire settled plan: slice, test, pull request, CI, review, merge, cleanup, next slice. The kit removed most of the command pipeline and design-state machinery it had spent months constructing.

Last week the repository appeared to be building LLVM for project management.

This week it deleted the intermediate representation.

Elsewhere, HotCorners acquired licensing, automatic updates, profiles, per-display behavior and real release packaging. Licensing reached sixteen landed slices and stopped just before the proof that requires the deployed authority and actual product. Docker-BuildAgent completed its original 2.0 documentation program, added the missing configuration integration, then red-teamed the release pipeline hard enough to discover that “publish exactly once” contains rather more than three words.

# Shipped Work

## SubZeroDev.AgentKit

[AgentKit PR #436](https://github.com/The-Running-Dev/SubZeroDev.AgentKit/pull/436) replaced the old command loop with a much smaller operating model.

`/next` now drives a complete implementation plan without requiring `/slice`, `/pr`, `/check`, `/resolve`, `/track`, `/clean`, `/handoff`, session-boundary banners or per-slice issues. Twelve commands remain. Design becomes a write-once specification during execution; differences are disclosed in the pull request and reconciled later only when requested.

The first version of that redesign immediately found the ordinary problems of long-running automation. Follow-up work made `/next` resume open pull requests and unmerged branches, read completion state from `origin`, survive failed fetches, avoid stopping for update notices, and guard files that were already uncommitted when the run began.

The current AgentKit suite reports **252 passed, 4 skipped**.

## HotCorners And Platform.Updater

HotCorners moved from “small Windows utility” into an actual desktop product.

It now consumes the published Licensing packages, reports licensed state, persists signed evidence, and can activate explicitly without gating features. It also consumes the new `SubZeroDev.Platform.Updater` package for consent-based update checks, channel selection, safe restart coordination, Setup/MSI/portable distributions, release feeds, checksums and preserved application data.

The product surface expanded substantially: system/light/dark themes, dwell-progress feedback, more Windows actions, named profiles, per-display corner overrides, foreground exclusions, modifier-selected alternate actions, safe interactive corner testing, improved settings, import review and searchable action selection.

The release story was corrected during the week. The earlier 1.0.0 line was withdrawn from the new updater path, and test builds now use `1.0.0-preview.N`. The last explicitly reported complete HotCorners suite before the final licence-only change was **340 passing tests**.

`SubZeroDev.Platform.Updater` became a reusable .NET 10 component rather than code embedded in HotCorners. It validates feeds and exact asset sets, bounds networking and downloads, supports signed packages, preserves update backoff and install outcomes, builds NuGet and symbol packages, and verifies WPF and WinUI consumers. Its latest reported package gate passed **130 tests** plus real portable A→B→C update validation.

## Docker-BuildAgent

Docker-BuildAgent landed S8-S12, completing the original twelve-slice 2.0 program, then added S13 because the new configuration system still was not called by the actual builds.

The repository now includes validated YAML and JSON examples for every build type, makes the PowerShell module select its own image version, prevents documentation from naming nonexistent features, defines one ownership source for every public-surface document, and gives 2.0 one migration and promise page. S13 then connected project configuration to the four real build entry points before any target runs.

A later documentation and red-team pass hardened the release path: `latest` moves only after the release is published; the updater owns its notification; version claims begin with an atomic Git ref; and every published sink records an artifact identity so a resumed release skips work only when the held artifact actually matches.

The latest reported full solution run passed **733 tests**. Version 2.0.0 remains unreleased, and the new release pipeline is still not wired into the live workflow.

## SubZeroDev.Licensing

Licensing landed S11-S16.

Hostile input now stops at the authority edge. The in-memory store and PostgreSQL adapter share one 26-test behavior suite. Windows machine identity comes from the 64-bit `MachineGuid` source with no fabricated fallback. A sample application demonstrates activation, atomic evidence persistence, restart and offline verification. Five packages are versioned and packed repeatably. A 109-entry evidence map ties the brief to tests, fixtures, CI jobs and review artifacts.

The map deliberately exposes eleven missing entries under Real Product Proof.

S17 groundwork added the GHCR image, Portainer stack, proxy-network topology, deployment workflow and VPS proof runbook. It did not connect to the VPS and does not claim the final HotCorners proof. Licensing is therefore **16 of 17 slices landed**, with the last slice now blocked on real deployment and product evidence rather than more internal architecture.

## Game Engine And Data.Json

`subzerodev-data-json` 0.3.0 now exports the canonical serialization and SHA-256 primitives. Game Engine removed its local canonical serializer and direct hashing dependency, consumed the published package, and kept consumer, package, documentation, site and host verification green.

Game Engine then landed W116-W119.

Campaign load now rejects collection-field typos before play. Simulation campaigns can own need drift, weekly time, late fees, eviction ladders, performance drift, event strangeness, every fixed action price and the remaining per-action physics. Omitted values preserve the old behavior byte-for-byte; explicit values produce deterministic divergence between otherwise identical campaigns.

W119 finished at **2,038 passing tests across 110 files**, with replay and golden fixtures unchanged.

## SkyNetHR

SkyNetHR finished a large operator and transport pass.

Codex `exec --json` command executions now appear as tool calls. Operator denial reasons reach the agent. Session end reasons are persisted and shown. Codex file changes render as labeled diffs. Claude hook lifecycles become vendor-neutral transcript events without storing hook output. A failed Codex resume gets one bounded fresh-thread recovery. Agent selection comes from the server's provider inventory instead of hard-coded client names.

Most significantly, Codex app-server command and file-edit approval requests now reach the existing per-call permission UI with exact RPC identity, stale-answer protection and host auditing. The live production adapter completed command and file-edit allow/deny probes across resumed context.

The latest reported suite passed **893 tests with 6 skipped**. The per-call approval implementation intentionally moved before the older preauthorized-session contract was reconciled; that documentation debt remains explicit.

## Git Service And Platform

Git Service landed S41-S49, S51 and S53, plus part of S50.

Terminal outcomes and parked work now notify operators. Interrupted work is recovered or parked before repository mutation. Boot keeps takeover evidence. Clone materialization fails closed. Composite operations preserve branches they did not merge. Error kinds describe actual failures. Tool and response-body waits are bounded. Health and console views report effective authority and real state. Watcher auto-merge is pinned to the commit it pushed. First-use watcher delivery can materialize its clone. Tampered watcher directories stop that repository and page once.

Platform landed S19-S22 of the generic bearer path: unclaimed credentials refuse correctly; fixed signing keys can come from configuration; discovery refreshes keys in the background without request-time networking; and one issuer pattern can represent many customer tenants without collapsing their identities.

# Meaningful Progress

Setup-Windows continued converting a personal rebuild process into explicit machinery. Interrupted rebuilds now stop instead of restarting blindly; staging failures close the ledger and release machine ownership; the real vault now satisfies the snapshot witness; application state returns as declared units; engine plumbing no longer carries private payload locations; and rebuild/config-sync resolve the machine profile carried by the binding rather than a second engine-side file.

The latest Setup-Windows full run reported **382 passed and 2 pre-existing NextDNS failures**. This is progress, not a green suite, and no bare-metal or VM rebuild was claimed.

HotCorners also produced the clearest product evidence of the week: Platform.Updater was extracted because another desktop application should be able to consume the same update and packaging mechanics. The abstraction is no longer justified only by its author.

# Decisions

- AgentKit optimizes for a continuous plan execution rather than command-by-command workflow ceremony. Design records no longer act as an execution-time state machine.
- HotCorners preview builds use `1.0.0-preview.N` and the preview channel until 1.0.0 contents are settled.
- HotCorners replaced the MIT licence with a proprietary preview licence after `1.0.0-preview.1` had already been built from the MIT tree. The new text has not had legal review and names no governing law.
- Update packages must be signed when a publisher key is pinned; the updater accepts public verification keys only.
- Docker-BuildAgent release recovery is identity-based. Existence is insufficient evidence that a previously written artifact is the right artifact.
- Game Engine owns mechanics and defaults; campaigns own balancing values once those values become configurable.
