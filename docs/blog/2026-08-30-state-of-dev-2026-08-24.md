# State of Dev

## Week of August 24, 2026

<!-- truncate -->

Somewhere around repository nineteen, the week stopped pretending to be about finishing projects.

AgentKit started measuring the cost of the development process itself. Game of Life acquired its own content pipeline and began filling an actual simulated life with jobs, money problems, bureaucracy, and bad luck. Git Service proved more of its deployment and recovery story against real systems. SkyNetHR spent the week discovering all the exciting ways network clients can refuse to behave. The Game Engine added more mechanical regression boundaries.

Then HotCorners appeared and went from an empty repository to a red-teamed design, contract, and nine implementation slices before any code existed.

This appears to be the current definition of restraint.

# Development Completed

## SubZeroDev.AgentKit

AgentKit continued becoming less of a command collection and more of the operating system around AI-assisted development.

The design-state work advanced through artifact-inclusive context measurement, retired companions, decision absorption through `StatedIn`, explicit decision scope, question resolution, and stronger drift detection.

That work also exposed the cost of the system itself.

The first weekly repository telemetry report measured the entire development estate rather than estimating from a few memorable sessions.

The result was substantial:

- 324 primary agent sessions plus 65 subagent transcripts;
- 28,574 model calls;
- 65 hours and 31 minutes of measured active agent time;
- 285 commits;
- 120,888 lines added and 11,149 removed;
- 19 active repositories.

More importantly, the report identified where the waste actually lives.

Long sessions dominate context cost. Housekeeping consumes an absurd amount of model capacity. `/clean` ran 134 times. Forty-two of those were repeat runs inside sessions that had already cleaned once.

The obvious optimization is now less "use a cheaper model" and more "stop hiring an AI to operate a broom."

That work has already started. `/clean` now hands off to `/next` instead of blindly entering a `/track` loop, derived tracker state can bypass unnecessary PR ceremony under narrow conditions, and Codex sessions now carry an explicit tier stamp instead of trying to rediscover their own configuration from a sandbox that cannot read it.

The tooling has reached the inevitable stage where it is now optimizing the tooling used to build the tooling.

## SubZeroDev.GameOfLife

Game of Life had one of the busiest weeks in the estate.

The repository stopped being specification-only and became the publication authority for its own simulation campaign content.

The Game Engine remains a dependency. The game owns the game.

That boundary now has an actual content toolchain:

campaign sources;\
deterministic export;\
committed portable JSON;\
manifest generation;\
a clean check that proves the generated content matches the sources;\
and CI that refuses stale or partially published output.

The path was then designed, contracted, sliced, and immediately started receiving content.

The initial job system now contains multiple employers, career paths, promotion ladders, skills, wages, and such distinguished positions as:

`Person Blamed When Wi-Fi Stops`

Random events followed, covering employment, money, purchases, crime, bureaucracy, transportation, and business.

A tax notice can now schedule a later tax penalty.

The simulation is progressing nicely toward accurately modeling adulthood.

## SubZeroDev.GameEngine

The engine spent the week making regressions increasingly difficult to hide.

W95 completed batch-invariance evidence for deferred world effects.

W96 introduced mechanical gates around several previously observed regression classes, including batch invariance, fixture retention, envelope ownership, audit-reason completeness, and per-kind event severity.

W97 then consolidated shared execution pipelines and made projection copying a kernel-level guarantee rather than something every game kind has to remember independently.

The package remains at `0.10.0`.

The verification surface is now large enough that one recent run covered 1,395 engine tests before even reaching the host, documentation, package-consumer, and deployment gates.

W98 has reached its contract gate around campaign catalogs, progress, visible stat ranges, and cross-kind terminal identity.

The engine is increasingly spending its time proving that future engine work cannot casually break previous engine work.

This is considerably less exciting than adding another game kind.

It is also how another game kind becomes safe to add.

## SubZeroDev.GitService

Git Service continued being tested against reality rather than polite fixtures.

The second-repository proof drove a real repository through branch preparation, staging, commit, push, pull request creation, checks, merge behavior, restart recovery, and reconciliation without a human reaching underneath the service to run Git manually.

That exercise found real contract gaps.

Auto-merge conflict detection did not behave the way GitHub's command-line surface initially suggested it would. The service now checks the actual pull request mergeability state before enabling auto-merge.

Deployment verification also became a first-class tool. The new companion check verifies the deployed commit and then performs a real authenticated MCP session against the running service.

Rollback was exercised against an actual container and persisted volume rather than documented as a future act of faith.

Windows then contributed its traditional support by revealing that `execFileSync('npm')` does not mean the same thing there as it does on Linux.

That is now fixed too.

## SubZeroDev.SkyNetHR

SkyNetHR spent the week hardening the parts of agent infrastructure that only become interesting when clients stop cooperating.

Live SSE and WebSocket subscribers now have real backpressure protection instead of being allowed to accumulate memory indefinitely.

The CI environment then demonstrated that backpressure is itself platform-dependent enough to require a larger fixture and an explicit period where the test client refuses to read anything at all.

Both Windows and Linux now pass the final test.

Vendor-neutrality enforcement also expanded beyond the original directories and immediately found vendor-specific assumptions that had escaped into edge code.

Claude adapter records that were previously dropped inline are now governed by named ignore lists so genuinely unknown records become visible instead of silently disappearing.

Codex transport detection is cached per process instead of running blocking probes every time another session starts.

Rejected async route handlers now correctly reach their error boundary instead of producing a hung request and an unhandled rejection.

SkyNetHR remains an HR system whose main employees are command-line processes.

Management is becoming stricter.

## SubZeroDev.WinGet

The self-hosted WinGet work gained a dedicated design sequence rather than being mixed into the existing package work.

The design was checked against the actual WinGet client implementation, including explicit source behavior, authentication, caching, rollback, and deployment assumptions.

That research already overturned one signed-off cache decision when the client source demonstrated that an absent cache header did not mean what the earlier design assumed.

The design changed.

Reality remained unmodified.

The repository also continued absorbing AgentKit infrastructure and tightening its own design-state and documentation boundaries while the private distribution path moves toward implementation.

## SubZeroDev.PSGenerator

PSGenerator started turning BuildAgent discovery into an evidence pipeline rather than a collection of special cases.

A maintained BuildAgent-shaped fixture now captures what the generator can and cannot infer from NUKE, C#, generated metadata, and PowerShell dispatch today.

The first fixture immediately found a real bug: maintenance scripts were being inferred as commands despite explicitly marking themselves as maintenance.

That is fixed.

The next layer now exists as well: a `CommandEvidence` schema, normalized evidence collection, and a redaction pass that prevents defaults or configured values marked as secrets from leaking through inspection output.

Inference is becoming less:

"I found a thing."

And more:

"I found a thing, here is where it came from, how authoritative it is, and no, I am not printing the password."

Progress.

## SubZeroDev.HotCorners

HotCorners appeared.

There was a brief.

Then a design.

Then a red-team pass found nine defects.

Then the design was rewritten.

Then another red-team pass found eight more defects.

Then those were adjudicated.

Then the design was rewritten again.

Then the contract appeared.

Then nine vertical implementation slices appeared.

There is still almost no application code.

This is probably the most disciplined new project currently in the organization, which feels deeply suspicious.

The first implementation slice will have to prove the two assumptions the design cannot settle on paper: that the polling model fits its CPU and latency budgets, and that the chosen hidden top-level window actually receives the Windows broadcasts the architecture depends on.

The Win32 API has therefore been invited to the next meeting.

# Major Milestones

The development process now has measured weekly telemetry instead of anecdotes about token usage.

The most important finding is not the total volume.

It is the distribution.

Seventy of 324 measured sessions crossed the 150K context warning threshold. Those 70 sessions consumed 69 percent of the week's cache-read volume.

Housekeeping-only sessions represented 219 of 324 sessions and consumed roughly a third of the week's cache-read volume.

That gives AgentKit a concrete optimization target.

Game of Life also crossed an important boundary by taking ownership of its own authored content while leaving mechanics inside the Game Engine.

Git Service proved deployment verification and rollback against a real running service.

SkyNetHR now has backpressure behavior proven on both supported CI platforms.

And HotCorners completed an entire design pipeline in the time normally reserved for deciding whether a project needs a README.

# Conclusions Reached Entirely By Accident

AI implementation is no longer the expensive part.

Repeatedly loading enough history for the AI to understand what it is implementing is.

Mechanical commands should become mechanical programs whenever possible.

A repository having `design/state/` does not mean it has adopted every design-state mechanism that might live underneath that directory.

Generated state should not require a ceremonial pull request merely because a model happened to generate it.

Real platform tests remain significantly more informative than clever mocks.

A specification that predicts reality incorrectly is the thing that changes.

And apparently the safest way to begin a Windows utility is to argue with its architecture twice before writing the utility.

That remains the problem.

# Challenges

Context size is now an engineering constraint, not merely an API bill.

The current warning identifies oversized sessions but does not yet change behavior strongly enough. The telemetry makes that obvious.

AgentKit also has an unresolved closure-budget problem. Once the actual file a session opens was counted as part of its orientation closure, many units crossed the 16 KB ceiling. The checker is now measuring the real thing. The architecture still needs to decide what to do about what it found.

Several repositories have also adopted only part of the design-state tooling, particularly the work mirror, without adopting the full state corpus and projection. Tooling that infers semantic adoption from directory presence keeps discovering why that is insufficient.

Cross-platform verification remains productive in the usual way: Linux and Windows continue agreeing on the contract only after independently finding different ways to break the same test.

# Looking Ahead

This week produced a useful transition.

The ecosystem is no longer only building software.

It is measuring how the software gets built.

That changes the optimization problem.

The models are already fast enough to produce implementation at a rate that would have been absurd a few years ago. The bottleneck is increasingly context, coordination, verification, repository state, and deciding which parts of the workflow require reasoning at all.

AgentKit is beginning to encode that distinction.

Git Service is making repository operations deterministic.

SkyNetHR is turning agent processes into manageable workers.

The Game Engine is making mechanics reusable.

Game of Life is proving the mechanics against actual authored content.

WinGet is turning local software distribution into infrastructure.

HotCorners is using the same design machinery before implementation exists.

The next major efficiency improvement may therefore have very little to do with a better model.

It may simply be making the models stop doing work that never needed a model in the first place.
