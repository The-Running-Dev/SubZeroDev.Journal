# State of Dev

## Week of 2026-09-21

This week produced 161 merged pull requests across The-Running-Dev.

That number is less interesting than what changed: HotCorners acquired a real public release, Docker-BuildAgent moved from 2.0 architecture into seven landed slices, SkyNetHR completed the five-slice operator-experience batch defined last week, Licensing reached S10, and AgentKit continued turning assumptions discovered in adopter repositories into shared executable rules.

Apparently the development system's reward for becoming reusable is that every edge case can now fail in several repositories at once.

# Shipped Work

## SubZeroDev.AgentKit

AgentKit now checks once per session for a newer compatible installation, shows the intervening commits, and asks before upgrading. `/autoupdate` and `/autoupdate-env` expose the persistent and per-environment controls without pretending a child process can rewrite its parent's environment.

The shared runtime also gained macOS CI, an installer verification mode, safer PR-branch selection, repository-scoped `gh` execution, more portable design-state checks, and release/documentation hardening.

Most importantly, companion files can no longer merely *claim* to narrow authorization. AgentKit now declares the allowed action vocabulary and verifies that a `tightened-authorization` companion is actually a subset of its base skill's authority.

[AgentKit merged 29 pull requests this week](https://github.com/The-Running-Dev/SubZeroDev.AgentKit/pulls?q=is%3Apr+merged%3A2026-09-21..2026-09-27).

## SubZeroDev.HotCorners

HotCorners completed its v1.0.0 release path with version metadata, Windows CI, a tag-gated release workflow, checksums, public documentation, an MIT license, and an explicit warning that the executable is unsigned. The README now links directly to the v1.0.0 release.

The application itself became much less like a demonstration: no launch console, a real application icon, safer settings-window sizing, browse controls for launch and command targets, test controls for unsaved actions, fullscreen exceptions by executable path, complete import review, and validation that enabled actions cannot save empty targets.

The design state also caught up. Eighty-seven unplaced decisions were resolved, five missing log records were created, and the oversized App unit was split at the snapshot publisher.

## Docker-BuildAgent

Docker-BuildAgent landed S1 through S7 of its 2.0 program.

The product can now derive and compare its public surface, update a running container under a durable lock, publish a version exactly once, restore the prior container when a replacement fails health checks, clear an abandoned lock explicitly, validate one YAML or JSON project configuration completely, and resolve values through one six-tier precedence model.

The important theme is refusal before mutation. Unknown surface changes fail closed. A bad configuration reports all known errors before a build starts. An unhealthy replacement restores the retained prior container instead of reconstructing one from memory.

## SubZeroDev.SkyNetHR

The S33-S37 batch is complete.

SkyNetHR now explains token burn by transport-reported component and turn, renders recoverable Claude Edit/Write diffs as read-only evidence, keeps session identity and cost visible in the masthead, detects repeated tool calls and repeated sequences diagnostically, and demotes conservative classes of agent throat-clearing at Compact verbosity without deleting stored events.

The runtime lease can also reclaim a holder tied to a displaced `server.lock` generation after container recreation. One Windows CI timing failure was traced to a test budget with insufficient scheduler headroom and corrected; the broader cross-suite Windows flake investigation remains open.

## SubZeroDev.Licensing

Licensing landed S6 through S10.

The system now gives bounded, specific answers for invalid keys, wrong products, wrong callers, and incompatible authorities; supports activation revocation and active-seat counts; holds allowances under concurrent activation; disables licenses without invalidating already-issued evidence; and maps connection, DNS, TLS, timeout, redirect, oversized-response, and future-protocol failures into the promised client result model.

S10 completed with 290 passing solution tests.

## Game Engine, Git Service, And WinGet

Game Engine now seeds a simulation's starting location and ships the Revision 5 `WorldGraphView`: a deterministic client-facing projection containing the reachable definitions, positioned map and entities, build and staff options, incidents, alerts, and explicit blockers without leaking private runtime machinery. W115 completed with 1,705 passing tests across 104 files.

Git Service now parks a clone when the watcher's declared and observed path sets disagree, refuses malformed UTF-8 before tool dispatch, and requires an authenticated console session plus CSRF protection for attention-clearing mutations. OAuth client registration is bounded and no-op token revocations no longer manufacture audit events.

WinGet fixed a false-green live-test gate: a selected test that skips or never runs now fails the target instead of allowing `dotnet test`'s successful exit code to masquerade as complete execution.

# Meaningful Progress

Platform moved its post-D5 identity work from loose issues into explicit architecture. The current direction treats Identity as a framework seam plus a module that owns no users, keeps permissions out of login tokens, and defines a generic bearer path with provider-specific escape hatches still under design.

Git Service converted its remaining open backlog into S40-S52. S40 landed immediately; twelve slices remain, including recovery, clone integrity, truthful errors, bounded waits, watcher finalization, first-use cloning, and a real-repository evidence harness.

Setup-Windows began turning the Windows rebuild process into tracked work: the public/private repository boundary was tightened, evidence moved under Git LFS, bootstrap behavior stopped depending on a question, and stale open design items were converted into issues.

Data.Json settled the J9 direction: published campaign-manifest digests are the content identity evidence, Adventures owns loading and verification at the host boundary, and Game Engine retains campaign-version semantics. Implementation remains open.

# Decisions

- HotCorners is MIT-licensed and ships v1.0.0 unsigned rather than delaying for a signing identity. The SmartScreen consequence is documented, not hidden.
- AgentKit companion authorization is a machine-checked subset relation, not a reviewer intention.
- SkyNetHR diff presentation is read-only evidence. It does not apply, revert, stage, or otherwise act on an agent's changes.
- Docker-BuildAgent compatibility is allow-listed: an unclassified surface difference is breaking until somebody explicitly proves otherwise.
- Platform identity remains a framework seam; product-owned users and permission-bearing login tokens are not being smuggled into the shared module for convenience.

# Open Items

- Docker-BuildAgent has S8-S12 remaining: examples, module/image version alignment, documentation truth, migration guidance, and final ownership cleanup. The live publishing path also still needs to be wired through the new release pipeline.
- Licensing has S11-S17 remaining: hostile-input boundaries, in-memory storage parity, Windows machine identity, sample integration, packaging, evidence mapping, and the real HotCorners consumer proof.
- Git Service has S41-S52 remaining. S49 is contract-gated because safe watcher auto-merge needs an expected-head input.
- SkyNetHR still has an unmapped recoverable Codex `item/fileChange/patchUpdated` diff and the broader Windows full-suite flake investigation. This week's timing fix closes one instance, not the pattern.
- Game Engine still has a host-locale `localeCompare` ordering defect in World Graph and lacks several simulation tuning levers. Balancing the actual numbers remains consumer work, not an engine default masquerading as game design.
- AgentKit still needs signed release tags and published checksums.
- Platform's identity direction is designed and red-teamed, but the permission and provider-identity items are not yet implemented.
