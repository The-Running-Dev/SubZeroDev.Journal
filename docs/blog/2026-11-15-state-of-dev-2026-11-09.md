# State of Dev

## Week of 2026-11-09

<!-- truncate -->

## Shipped Work

### Infra And Deployments

[Infra v2.0.0](https://github.com/The-Running-Dev/SubZeroDev.Infra/pull/4) moved deployment authority into the Infra repository: app repositories now dispatch a revision while Portainer credentials remain centralized. Version 2.1.0 added third-party image support. Dashboard then completed its VPS migration through that path, removed Nginx Proxy Manager, and cleared the remaining Immich, Seafile, and Traefik leftovers. Adventures, BibleStudy, Journal, and SubZeroDev.com also adopted the Infra-hosted workflow. A deployment mechanism became a small municipal government.

### FileManager

The per-user product path landed across six merged slices: an in-process host, tray agent, unified Velopack package, signing and release infrastructure, public release workflow, and [HotCorners-based automatic updates](https://github.com/The-Running-Dev/SubZeroDev.FileManager/pull/36). Updates defer while the UI or a file operation is active, block new work during restart, and recover the current version after an aborted apply.

### BibleStudy

[Whole-Bible offline download](https://github.com/The-Running-Dev/SubZeroDev.BibleStudy/pull/34) now covers ESV, BSB, and CSB: 1,189 chapters per translation with pause, resume, integrity repair, and account isolation. Validation passed 159 unit, 196 integration, and 89 browser tests. The owner's 1,189 CSB chapters were imported without changing existing BSB or ESV content hashes.

### Journal

The Journal published the 145-entry backlog, added three subsequent posts, and reorganized discovery into Journal, Chronicles, Topics, and Projects. The reading overhaul preserved established routes and bodies while retagging 236 posts; validation covered 21 core routes, 46 tag routes, and two feeds.

## Meaningful Progress

### Runners

The runner-pool plan reached S4. Hosts now have layered inventory, lifecycle state, hold/resume controls, generated Linux Compose services, per-slot recreation, and image-context drift reporting. All 19 local test suites passed, but the S4 entry point still used fake Docker and GitHub clients. The real daemon remains stubbornly physical.

### MemoryKit And AgentKit

MemoryKit added bounded, attributed browsing and read-only Git repositories as memory sources, including later-commit following and automatic refresh. Cold-recall measurement closed with daily recall remaining opt-in. AgentKit then measured explicit MemoryKit navigation against automatic context: on the 121-record synthetic store, explicit selection found all three targets in ten CLI calls; automatic context found one under the default 8,192-byte budget in two calls. The result supports deliberate browsing, not a claim that ten calls are secretly fewer than two.

### DockerWatchDog

The TypeScript rewrite reached API, engine, web UI, image, release workflow, and cut-over files. The replacement image built at 544 MB, became healthy locally, served the API and SPA, and passed the reported lint, type, test, and build checks. Host parity and the live switch were intentionally left manual, so this is substantial progress rather than a completed migration.

## Decisions

- Deployment secrets are held by Infra; app repositories dispatch immutable deployment inputs instead of carrying Portainer credentials.
- FileManager updates wait for active UI and file operations, then use a maintenance barrier before handing control to Velopack.
- MemoryKit daily recall stays opt-in after measurement; bounded browse-and-select remains the explicit path for deeper retrieval.
- BibleStudy extended the existing translation adapter model under ADR-0007 instead of creating a second offline-content system.

## Open Items

- FileManager still needs an installed `v1.0.0-preview.1` to `.2` public-feed upgrade; no installed-update CI job exists yet.
- Runners still needs S9 acceptance against a real Docker daemon and runner. Legacy migration and add/retire work also remain beyond S4.
- DockerWatchDog still needs old/new host parity, Docker CLI 29 compatibility on QNAP, and the production cut-over. [GitHub sign-in](https://github.com/The-Running-Dev/SubZeroDev.DockerWatchDog/pull/9) remained open at the snapshot.
- AgentKit [issue #529](https://github.com/The-Running-Dev/SubZeroDev.AgentKit/issues/529) remained open for browse wording and capability-detection follow-ups. Six dependency PRs were also open; they are not accomplishments, merely weather.
