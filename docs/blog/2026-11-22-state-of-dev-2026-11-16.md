# State of Dev

## Week of 2026-11-16

<!-- truncate -->

## Shipped Work

### Plugins.GitHub

[Version 0.2.0](https://github.com/The-Running-Dev/SubZeroDev.Plugins.GitHub/releases/tag/v0.2.0) shipped on November 21. The release added explicit organization discovery, retained numeric-ID deduplication and existing repository filters, cleared the blocking audit findings, attested its release manifest, and moved npm publication to GitHub OIDC trusted publishing. A live check found 111 unique repositories across the configured accounts; the automated suite passed 316 tests with two live tests skipped. The package is now `@absolutezerodev/plugins-github`, because even namespace availability eventually becomes architecture.

### BibleStudy

[Scripture storage moved to verse tables](https://github.com/The-Running-Dev/SubZeroDev.BibleStudy/pull/35), and API.Bible was removed. Scratch-database imports completed with zero failed chapters across BSB, CSB, and ESV: 1,189 chapters per translation and 93,259 verses in total. Existing served chapters remain the compatibility copy, preserving offline hashes and manifests except for the documented one-time CSB cross-reference change. Validation passed 158 unit tests, 14 narration integration tests, and 84 browser tests.

### Infra And Uptime

Infra released [modules/app v2.3.0](https://github.com/The-Running-Dev/SubZeroDev.Infra/pull/11), adding an optional long-lived platform stack so ordinary deploys do not recreate databases or tunnel connectors. Cross-owner deployment support also landed for AbsoluteZeroDev repositories, including owner-specific read credentials. The module reported 30 passing OpenTofu tests. Separately, the new Uptime repository recorded the live Kuma layout: 57 monitors up, with two known 404 services paused. Monitoring now has documentation, which means it can begin disagreeing with reality in a controlled manner.

## Meaningful Progress

### Dashboard

Dashboard completed the GitHub discovery and import implementation: the worker discovers repositories through the pinned 0.2.0 plugin, the owner can review and group candidates, and imports are additive, revision-checked, idempotent, and explicit about their target projects. The merged slice passed 132 of 136 unit tests with four conditional skips and 18 browser tests. No real GitHub discovery or production import was run, so this is implemented and validated, not operationally proven.

The project also added a deterministic relationships view, grouped and filtered project lists, sensible default expansion, and a split production stack that keeps PostgreSQL, backups, and Cloudflare Tunnel outside ordinary app redeploys. Local split-stack smoke testing preserved platform container IDs while recreating the app and recovered readiness afterward. The production cut-over remains an operator step.

### Platform Identity

Platform now contains a Keycloak `members` realm as code, passkey sign-in, restricted account actions, an edge test using a real member token, security-event capture, and verified database backup metadata. The paired restore workload records security-event coverage off-host, replays reversible state, resets sessions, and blocks reopening across coverage gaps. The restore proof reached 48 of 48 checks after exposing and fixing two real defects; the integrated provider suite then passed 38 tests in CI.

None of this is deployed. The live realm, account migration, and complete-loss recovery remain outside the evidence. The week produced an identity system and, with admirable restraint, did not call it finished.

## Decisions

- The live game edge will use `game-api.subzerodev.com`, the Keycloak `members` issuer, and the existing public `game-cli` client.
- Dashboard imports merge into existing configuration; they never deselect projects merely because discovery omitted them.
- Long-lived services belong in a platform stack so an app release cannot casually restart its own database and tunnel.
- BibleStudy keeps chapter documents as the served compatibility format while verse, heading, footnote, and cross-reference rows become the queryable model.
- Security-event replay is not treated as magic: an uncovered gap blocks identity recovery rather than being reclassified as optimism.

## Open Items

- Platform identity still has production gates R1, D6, and OD-16, plus first-credential enrolment and token-lifetime decisions. The repository has no live VPS deployment path yet.
- Dashboard's production GitHub discovery/import remains untested. The S20 stack split is merged and Infra v2.3.0 is tagged, but the stop-and-apply cut-over has not been evidenced.
- BibleStudy still requires one CSB and ESV re-import to populate the richer derived fields. Search and side-by-side reading were explicitly not part of the verse-storage slice.
- [Infra PR #6](https://github.com/The-Running-Dev/SubZeroDev.Infra/pull/6), the optional Cloudflare Access gate, remained open. Five dependency PRs also remained open; they have been counted, not promoted to narrative.
