# Executive Summary

The largest architectural movement this week happened in three places.

First, SubZeroDev.GameEngine reached the end of the W108 `0.11.0` release-readiness program. The release candidate was packed, inspected, installed into a clean consumer, exercised against companion repositories, and reconciled against the actual constraints discovered during the rerun. Two remaining release questions were explicitly decided rather than left disguised as verification gaps. W107 and W108 are now closed.

Naturally, W109 through W113 were immediately opened for the GameOfLife capabilities that the previous content work proved were genuinely missing.

Second, SubZeroDev.Licensing became real software at considerable speed. The original in-process licensing concept was replaced by a deployed authority with PostgreSQL persistence, a reverse proxy terminating TLS, mounted secrets, authenticated operator operations, explicit wire contracts, concurrency rules, and seventeen implementation slices. S1 and S2 are already landed.

Third, AgentKit continued becoming the actual product behind much of the product development. Its design-state system now understands components as first-class units, derives invariant ownership instead of redundantly storing it, and continues tightening the difference between what a repository actually knows and what an agent would otherwise have to reconstruct.

The other major theme came from using Astra against the existing Game Engine and AgentKit process.

The interesting benchmark is no longer:

"Can a large agent recreate this repository?"

That mostly benchmarks the agent.

The more useful question is:

"Can AgentKit package enough architecture, contract, state, evidence, and current work that Astra can execute future repository work with much less supervision?"

That is a considerably more useful problem.

It is also recursion.

Again.

# Development Completed

## SubZeroDev.GameEngine

The Game Engine completed one release cycle and started another.

W108 began with a full rerun of the `0.11.0` candidate against the repository and its real consumers rather than trusting historical evidence.

That rerun did exactly what it was supposed to do.

It found problems.

GameOfLife initially failed to compile against the candidate because newer Simulation campaign requirements had reached the engine without the companion content being updated.

Platform's durable/PostgreSQL profile initially could not run because PostgreSQL was unavailable in that environment.

Documentation and host-image gates depended on Docker.

Two remaining criteria were not technical verification problems at all. They were policy decisions.

Those gaps were worked down rather than waved through.

GameOfLife was corrected and reverified.

The Platform PostgreSQL profile was later run successfully against the candidate.

The two actual policy questions were resolved explicitly: consumer recovery remains rollback to a known published version followed by a corrected higher release, and browser-shelf parity belongs to the Adventures client contract rather than being falsely asserted inside the Game Engine repository.

W107 and W108 are now closed.

The `0.11.0` candidate is therefore release-ready by the program's own criteria.

Publication remains an explicit action rather than something readiness performs automatically.

This is a reassuring separation of responsibilities.

The next program was already waiting.

W109 through W113 capture five GameOfLife engine blockers discovered by writing actual simulation content rather than inventing future features from a whiteboard.

W109 is landed.

Simulation modifiers can now target:

`player.reputation.<key>`

The reputation value behaves like the existing skill modifier path: active modifiers layer over stored state, values clamp to the intended range, expired effects disappear without mutating the base, and missing keys remain missing instead of becoming convenient zeroes.

W110 is also landed.

NPC definitions can now author starting memories, including validation that their description keys resolve correctly.

The helper that seeds those memories exists and is tested.

It is not yet wired into full NPC creation because the engine currently lacks a reducer that materializes `NPCState` from `NPCDefinition` in that path.

That gap remains explicit rather than being quietly solved inside an unrelated slice.

W111 through W113 remain:

collection-aware `exists` and `count` conditions;

weekly item running costs;

housing utilities and transport costs with the required persisted-state migration.

The order is deliberate.

The changes that do not alter committed state land first.

The changes that move cash trajectories and replay fixtures come later.

The state-shape migration comes last and alone.

This is considerably less exciting than implementing all five on Friday afternoon.

It is also considerably less likely to ruin Saturday.

## SubZeroDev.AgentKit

AgentKit continued tightening its representation of engineering state.

S31 removed `Invariant.Owner`.

That field had reached the point where reality no longer fit it: some invariants were held by one unit, some by several, one by everything, and one by nothing.

Rather than teaching `Owner` progressively stranger cardinality rules, ownership is now derived from the units whose `Binds` edges reference the invariant.

The generated projection now says:

`Held by`

Which is what the system actually knows.

The change also reduced the largest live context closure from roughly 14 KB to 13 KB.

This is exactly the kind of result AgentKit exists to produce:

fewer duplicated facts;

less context;

more derivation.

S32 then added `component` as the fifth unit kind.

A repository can now record assemblies, modules, packages, or equivalent compilation units as part of its machine-readable design state instead of pretending every architectural unit is a command, script, document, or abstract product concept.

This matters for projects such as Platform and Licensing where package or assembly boundaries are architecture.

The design-state checker was immediately used hard enough to find a bug in the new behavior.

A `component` record still needs to be checked against an empty artifact universe if the repository declares no component glob. The first implementation incorrectly skipped that direction entirely.

The regression is fixed.

The full AgentKit tool suite reached 397 passing Pester tests during this work.

More interestingly, this week's Game Engine/Astra exercise reframed where AgentKit should go next.

The goal is not to turn Astra loose on Game Engine and ask whether it can reverse-engineer several months of work.

That would be a very elaborate free benchmark.

The useful path is to treat Game Engine as evidence of the development process that created it, inspect AgentKit against that evidence, and improve the kit so a future repository can be handed to Astra with architecture, contracts, work state, invariants, decisions, and verification already organized.

The process is becoming the reusable artifact.

Which naturally means the process is now being used to redesign the process.

## SubZeroDev.Licensing

Licensing had the week's largest zero-to-infrastructure transition.

The brief originally described an in-process authority.

That model no longer matched the intended product.

The authority is now deployed.

That required rewriting almost every important assumption.

The MVP has one authority deployment per licensor.

PostgreSQL is the durable adapter.

A separate authority host owns HTTP transport, authentication, validation, startup composition, and schema initialization.

A reverse proxy terminates TLS.

Secrets arrive through fixed read-only mounted files.

The host itself owns no certificate.

The application receives opaque license evidence and decides where that evidence lives locally.

Concurrency is enforced in storage, not by hoping one authority process remains the only authority process.

License activation and revoke operations acquire the same row lock first.

A partial unique index protects active activation uniqueness.

The design now has an actual deadlock argument rather than a cheerful lack of deadlocks observed so far.

The wire contract was then written.

It includes versioned routes, request and response envelopes, reason codes, validation order, body limits, fixed credential forms, explicit decoder bounds, retry semantics, and 34 initial invariants.

The implementation program was cut into seventeen slices with 124 criterion identifiers.

S1 tests the riskiest assumption first:

Can the real authority topology boot safely?

It now can.

The acceptance setup runs real PostgreSQL, the actual authority host, and the actual reverse proxy in containers.

Signing-key custody is checked.

Schema initialization runs under an advisory lock.

The host runs as non-root.

The built image is checked for secret material.

Windows and Linux build paths both pass.

S2 then added operator product registration.

An authenticated operator can register a product and receive its client credential.

Only the SHA-256 digest is stored.

Repeating product creation before the first license exists reissues the credential.

After a license exists, credential replacement is deliberately not supported in the MVP.

Rotation is post-MVP.

This is a particularly useful example of refusing to turn every security concern into immediate platform scope.

The project now has two of seventeen slices landed, roughly 12 percent by slice count.

That sounds small.

It is less small when those two slices contain the deployment topology, database bootstrap, secret custody, authenticated operator edge, product persistence, credential semantics, real container acceptance suite, and both Windows and Linux verification.

The foundation is no longer theoretical.

## SubZeroDev.SkyNetHR

SkyNetHR's current 32-slice architecture was already landed.

This week was about finding what the architecture had still missed.

The Windows service installer finally resolved its NSSM support rule.

The implementation now refuses NSSM below version `2.25`.

The important reason is graceful shutdown.

Older NSSM configurations commonly rely on `AppNoConsole=1` on newer Windows hosts. That setting prevents the Ctrl\+C path SkyNetHR uses to let the child process shut down gracefully.

The installer therefore checks the executable's Win32 file-version resource before executing any NSSM command and fails if the version cannot be trusted.

The policy is unconditional rather than attempting to maintain a matrix of Windows releases against NSSM workarounds.

The repository then continued the more ordinary job of discovering process-manager edge cases.

If a child spawns and the subsequent write to it fails, the tracked process tree is now explicitly killed instead of merely ending the logical turn and leaving the process alive.

If an operator answers a pending permission request but the response cannot be delivered because the child disappeared, the audit trail no longer falsely records that the operator's decision reached the agent. The permission resolves as:

`cancelled_process_exit`

The operator decision remains evidence of what was attempted, not evidence of delivery.

The SSE backpressure path also stopped writing an `id:` line on a `replay_gap` frame, matching the contract's rule that a replay gap reports the last confirmed watermark rather than minting a new resume point.

The current JavaScript test suite is around 500 tests, with additional Pester coverage for the Windows tooling.

A separate spill catch-up timing flake remains tracked.

So does a WebSocket frame-discriminator duplication found during reconciliation.

SkyNetHR has therefore reached the pleasant stage where most bugs require explaining process identity, protocol semantics, asynchronous lifecycle ordering, or Windows.

Human Resources has never been more authentic.

## SubZeroDev.WinGet

The private/self-hosted WinGet work remains in evidence-gathering rather than production implementation.

That is deliberate.

Two questions, FC24 and FC25, need real observations around Windows Package Manager authentication behavior before the production self-hosted source is worth building.

The repository now contains a throwaway observation harness rather than asking someone to assemble the experiment manually each time.

The harness can create the Entra application, start the minimal information endpoint, establish the certificate and hosts prerequisites, register the observation source, launch Windows Sandbox, and optionally trigger the search that produces the WAM sign-in behavior being studied.

The setup was then consolidated into one orchestrator:

`Initialize-ObservationHarness.ps1`

with matching teardown.

What it does not do is automate the WAM consent interaction itself.

That is the observation.

Automating the thing being observed would be admirably efficient and completely useless.

The production self-hosted source therefore remains intentionally blocked on live Entra/WAM evidence rather than growing another twenty slices around an assumption that can be tested first.

## SubZeroDev.HotCorners

HotCorners remained active in hardening and reconciliation.

The original utility is far enough along that current defects are about failure disposition and consistency rather than whether a corner can detect a mouse.

One important issue discovered this week is that the snapshot publisher's worker loop can currently terminate after an escaping exception while detection continues operating against stale geometry.

That is worse than a crash because the software remains alive enough to look functional.

The design now has to decide how that failure should surface and whether it shares the existing stopped-state behavior.

HotCorners also continues exposing rough edges in the shared design-state tooling, particularly around repositories that have adopted some record kinds but not the entire current AgentKit corpus.

It remains scheduled as Licensing's eventual real-product proof.

This is convenient.

The licensing system gets a consumer.

HotCorners gets licensing.

Neither needs a sample application created solely to prove that two repositories can speak to each other.

# Architectural Decisions

## ADR: Release Readiness Does Not Publish The Release

**Decision:** Game Engine W108 establishes whether `0.11.0` is ready. Publication remains a separate explicit operation.

**Reason:** Verification should not create external state merely because the last checklist item became green.

**Consequence:** The release candidate can be fully proven without turning a verification session into an irreversible package publication.

## ADR: New Game Engine Capabilities Are Ordered By Blast Radius

**Decision:** W109-W113 land from additive read-path behavior toward fixture-changing behavior, with persisted-state migration last.

**Reason:** Independent additive changes are cheaper to review and prove before replay and migration churn begins.

**Consequence:** W109 and W110 can land without moving existing fixtures. W112 changes cash trajectories. W113 owns the version bump and migration alone.

## ADR: Invariant Holders Are Derived

**Decision:** AgentKit no longer stores `Invariant.Owner`.

**Reason:** The actual relationship already exists through `Unit.Binds`, and real invariants can have zero, one, several, or universal holders.

**Consequence:** One copy of the fact disappears, projection becomes more truthful, and context closure shrinks.

## ADR: Components Are First-Class Design Units

**Decision:** AgentKit adds `component` alongside the existing unit kinds.

**Reason:** Assemblies, packages, and modules are often real architectural boundaries and should not be represented indirectly.

**Consequence:** Repository design state can map compilation units explicitly without AgentKit inventing a universal build layout.

## ADR: Licensing Is A Deployed Authority

**Decision:** The licensing authority runs separately from client applications and persists through PostgreSQL.

**Reason:** Machine allowances, revoke, shared activation limits, and real-product proof require authority beyond one application process.

**Consequence:** Networking, authentication, transport limits, secret custody, concurrency, and deployment become part of the MVP instead of postscript infrastructure.

## ADR: TLS Terminates At The Reverse Proxy

**Decision:** Licensing's application host speaks HTTP internally and owns no certificate.

**Reason:** TLS and certificate management belong at the deployed edge, while the linked application packages should remain free of web-host concerns.

**Consequence:** The acceptance topology tests through the same proxy boundary used by the intended deployment.

## ADR: Product Credentials May Be Reissued Only Before The First License

**Decision:** Recreating a product can reissue its client credential until the first license exists. After that, rotation is outside MVP.

**Reason:** Supporting safe credential rotation after issued licenses requires additional lifecycle and recovery behavior.

**Consequence:** The MVP admits the limitation instead of hiding a partial rotation mechanism behind a comforting method name.

## ADR: SkyNetHR Requires A Modern NSSM Build

**Decision:** The Windows installer refuses NSSM versions below `2.25`.

**Reason:** Older deployment patterns can require `AppNoConsole`, which conflicts with SkyNetHR's graceful Ctrl\+C shutdown path.

**Consequence:** The installer fails before modifying NSSM state when the runtime cannot support the shutdown contract.

## ADR: Observe WinGet Authentication Before Building The Source

**Decision:** FC24 and FC25 are tested through a disposable harness before production self-hosted-source implementation proceeds.

**Reason:** Entra/WAM behavior is a stop condition for the design, not a detail to discover after deployment work is complete.

**Consequence:** Production work remains intentionally blocked until the platform answers the question.

# Notable Technical Decisions

Game Engine's reputation modifier uses the same derived-value treatment as skills rather than introducing another modifier pipeline.

NPC starting memories are authored now but not injected through a nonexistent state-materialization path merely to make W110 look more complete.

Game Engine's `0.12` migration work is isolated in W113 so only one slice owns the persisted-state version transition.

AgentKit's component artifact checking treats the repository's declared glob as the authority because the kit cannot infer every build system's component layout generically.

Licensing stores credential digests rather than plaintext client credentials.

Product and license operations use explicit row-lock ordering so concurrency semantics live in the storage seam rather than in one process.

Licensing secrets are mounted as files and subjected to custody checks rather than moving secret material into command-line arguments or images.

SkyNetHR reads NSSM's executable file-version resource directly because NSSM offers no useful version command.

SkyNetHR now distinguishes an operator decision from successful delivery of that decision to a child process.

WinGet's observation harness automates setup but deliberately does not automate the interactive authentication behavior being investigated.

And Sites is increasingly being treated as a fast product shell when writing another custom frontend would provide little architectural value.

# New Concepts and Ideas from the Week

## AgentKit As A Repository-To-Agent Compiler

The Astra evaluation produced the most interesting process idea of the week.

Game Engine is evidence of a development process.

AgentKit is supposed to capture enough of that process to make it repeatable.

The useful end state is therefore not:

"Astra is smart enough to understand Game Engine."

It is:

"AgentKit transforms an arbitrary repository into enough bounded context that Astra can work on it safely."

That means improving things such as:

design-state coverage;

architecture retrieval;

contract boundaries;

work selection;

verification evidence;

reconciliation;

and the handoff between reasoning and implementation agents.

This is a much stronger benchmark than asking an agent to recreate a repository whose answers already exist.

If a small project needs:

This does not remove backend architecture.

The business consequence is more interesting than the technical one.

# Challenges and Blockers

## Throughput Is Still Large Enough To Punish Small Mistakes

143 pull requests in one week is lower than some recent weeks.

It is still enough that tiny structural errors replicate quickly.

A stale AgentKit assumption propagates into multiple repositories.

A bad checker predicate creates false state across every target.

A release criterion with ambiguous ownership becomes a recurring blocker.

A convenience field such as `Owner` becomes a context tax in every design-state closure.

At this scale, small abstractions matter.

So do small mistakes.

## Cross-Repository Verification Is Becoming Normal

Game Engine now has meaningful relationships with GameOfLife, Adventures, Platform, and ServiceContract.

A release proof can fail because the engine is wrong.

It can also fail because the companion has drifted.

That is a better problem than pretending the repositories are independent.

It does make release verification look increasingly like a small integration program.

## Real Environments Continue To Veto Elegant Assumptions

NSSM version behavior mattered.

Docker availability mattered.

PostgreSQL availability mattered.

Windows process semantics mattered.

Entra/WAM behavior still matters enough that WinGet refuses to proceed without observing it.

The recurring technical lesson remains irritatingly stable:

Architecture describes what should happen.

The operating system is invited to review it.

## Product Generation Is Becoming Faster Than Product Selection

Sites can now produce usable product surfaces quickly.

Agents can produce implementation quickly.

The repository workflow can generate and review work quickly.

This makes choosing what deserves to become a maintained product more important, not less.

The limiting resource is increasingly not code.

It is attention.

This has not yet reduced the number of ideas.

# Looking Ahead

The most interesting change this week is that several previously separate experiments are starting to reinforce one another.

GameOfLife is generating Game Engine requirements.

Game Engine is providing a benchmark for AgentKit.

AgentKit is becoming a better way to hand repositories to Astra and the other implementation agents.

Licensing will eventually prove itself through HotCorners.

Private WinGet can eventually distribute HotCorners and the other Windows utilities.

Sites can put usable product shells around those utilities and infrastructure projects without another frontend project becoming the critical path.

The local-business concept can reuse the same bias toward configuration over bespoke implementation.

The meetup can become a place to show the resulting systems rather than explain abstractly that AI can write code.

The overall direction is becoming clearer.

The interesting asset is not any single repository.

It is the ability to turn a problem into:

a bounded brief;

a designed contract;

a sequence of executable slices;

verified implementation;

reusable infrastructure;

and a working product surface.

Then hand the implementation work to whichever agent is appropriate without having to explain the entire history again.

This was originally called "using AI to write software."

That description is becoming increasingly inaccurate.

The software is almost the side effect.
