# State of Dev

## Week of 2026-10-19

There were fewer pull requests this week. MemoryKit compensated by going from design documents to a complete twelve-slice implementation before the calendar could develop a defensive posture.

## Shipped Work

### MemoryKit

[SubZeroDev.MemoryKit](https://github.com/The-Running-Dev/SubZeroDev.MemoryKit) went from its initial design PR to the complete S1–S12 implementation, reconciliation, package verification, and two performance passes in eighteen merged pull requests.

The resulting v1 is local-first and server-optional:

- SQLite with WAL and FTS5 is the canonical store, with revision checks and idempotent operations preventing silent concurrent overwrites.
- A durable outbox exports history asynchronously. Git is the default provider; memory and no-history configurations remain valid.
- Archive, supersede, tombstone, restore, bounded deterministic search, namespaces, and core permission enforcement are implemented.
- The same service is exposed through the embedded SDK, CLI, local HTTP with bearer tokens, remote HTTPS with OIDC, and eleven MCP tools.
- Purge reports what it removed across the store, pending outbox, and available history instead of implying that unavailable history was erased by optimism.
- A packed tarball is installed into an empty consumer directory and exercised through its public CLI and TypeScript exports on Node 22.18 and 24, Windows and Linux.

The first complete package proof reported 165 passing tests. Reconciliation and the final contract fixes brought the suite to 171, while preserving the rule that memory-only and no-history consumers do not eagerly load Git.

The first performance pass reduced Git processes per exported revision from roughly eleven to five. The historical-revision index then changed the Ubuntu CI benchmark substantially:

| Measure | 1k Baseline | 1k Indexed | 10k Baseline | 10k Indexed |
| --- | ---: | ---: | ---: | ---: |
| Revision median | 94.29 ms | 5.95 ms | 928.20 ms | 8.15 ms |
| Drain throughput | 15.6/s | 53.5/s | 4.4/s | 27.8/s |

Every revision remained in the Git repository, and a missing or damaged index rebuilds from Git rather than becoming another source of truth.

This is implemented and installable from its verified tarball. It is not published to npm. The package name and scope remain deliberately unresolved.

### AgentKit

AgentKit added `/setup-project`, backed by SubZeroDev.GitHub’s canonical repository scaffolder and guarded publishing path. It can defer language selection, locate the authoritative checkout, verify repository state, preview the requested change, and refuse a later OpenTofu plan that drifts beyond the requested repository.

The review process is now bounded per deliverable: one independent review, one consolidated correction, and one targeted re-review, with risk-proportional depth and a small evidenced learning record. The budget survives sessions, models, and vendors. A third pass requires new authority rather than a sufficiently creative interpretation of “one more review.”

Questions now use decision cards where the host supports them, and AgentKit’s update policy is explicit: ask, update automatically, or stay off. Additional work added SSH-signed release tags with checksummed source archives, immutable stash evidence, ownership checks before reclaiming a plugin container after rollback, and a rule that a decision cannot close an issue until the cited decision actually exists on the default branch and says what the closing text claims.

### SubZeroDev.GitHub

Repository provisioning became cross-platform and less theoretical.

- The Node starter now generates TypeScript that really builds, tests, lints, and starts from compiled output. CI proves it on Ubuntu and Windows with Node 22 and 24.
- Target-scoped publishing validates the exact saved OpenTofu plan immediately before each apply. Unrelated creates, updates, replacements, destruction, and imports stop the run; `--force` does not waive scope.
- Project creation can defer language selection, with language added later through a conflict-detecting, idempotent operation.
- The PowerShell implementation and Pester suite were ported to TypeScript on Node 22.18+, with CI across Windows, Linux, and macOS. The final local verification reported 144 Node tests, nine real OpenTofu tests, and a passing generated-project smoke test.

MemoryKit is now registered through the same repository machinery. The new project tool has begun using itself, which is generally when the entertaining defects arrive.

## Meaningful Progress

### GodComplex — Consequences

No Game Engine pull request merged this week, so none of this is shipped.

The open pathfinding change replaces repeated edge filtering and a fully sorted open list with a per-call neighbour index and binary heap while preserving the exact canonical path. On the same measured setup, a 64×64 corner-to-corner route dropped from a 1,146 ms median to 4.65 ms; 2,355 tests passed, including seeded equivalence against the old implementation.

The stacked full-tick benchmark now exercises ten seeded workloads through the real twenty-system pipeline. Its committed Linux/Node 24 evidence covers 210 measured batches and 420 measured ticks with repeatability and split-batch parity checks. It measures capacity; it does not quietly convert one machine’s result into a supported map or guest limit.

The larger correctness set also remains open: branch initialization must be preserved, cached session state must become visible only after persistence commits, Windows CLI guards must actually run, and Adventures still needs durable content epochs rather than replacing its engine and archive whenever content refreshes.

### Cleaner

The Cleaner expansion remains design work.

PR #22 adds planned slices for app-installation detection, browser profiles read from each browser’s own profile list, and a developer-only importer that produces unusable rule candidates until a person supplies safety evidence. It is based on a study of CCleaner’s shipped engine files and explicitly separates observed behavior from inference.

It is stacked conceptually on the still-open red-team corrections in PR #21, while the HotCorners-inspired UI redesign remains open in PR #15. Firefox’s relative profile-path normalization is also unresolved in the current design. No new cleaning behavior shipped this week.

### HotCorners

The `v1.0.0` release was withdrawn and its tag deleted. The repository returned to `1.0.0-preview.3`; the next intended build is preview 4.

That reversal exposed a real test-isolation defect: six single-instance tests address the production mutex and hidden window, so an installed running copy can break the suite or receive a test message. The open isolation PR gives every test an immutable private identity. Its Windows CI evidence reports 510 passed, zero failed, and one existing unrelated skip. Useful proof, still awaiting merge.

## Decisions

- MemoryKit uses SQLite as canonical state and Git as rebuildable asynchronous history evidence. Git indexes may accelerate reads but never become authoritative.
- MemoryKit history idempotency is scoped by operation, memory, and revision because one supersede operation exports two records. `GitHistory` is public through a lazy subpath, not an eager root export.
- MemoryKit configuration remains an open-time input; namespace policies are persisted when created. A new configuration-file format is not being invented merely because the word “init” sounds administrative.
- AgentKit review is bounded per deliverable, with depth inferred from risk. The entry point runs before the review.
- SubZeroDev.GitHub’s project tooling runs on Node across the three desktop operating systems, and a project may exist before its implementation language is chosen.
- HotCorners `1.0.0` is withdrawn. Current evidence supports preview 3, not stable-release theatre.
