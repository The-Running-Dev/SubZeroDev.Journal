# State of Dev

## Week of 2026-10-05

The quiet part of the week was limited to the parts not being rebuilt.

<!-- truncate -->

## Shipped Work

### Shared Build Infrastructure

`GitHub-ActionTemplates` was rebuilt as a callable Actions library, with reusable documentation, Node, PowerShell, and npm-package workflows; explicit verification-gate manifests; release helpers; coverage and test reporting; and branch-protection result jobs. Follow-up fixes taught it where browsers live on Windows and macOS and that `.` is, occasionally, a valid project directory.

Sixteen repositories adopted the library this week: nine moved documentation builds to the shared workflow, and seven moved application or package CI to the shared Node/PowerShell workflows. The migrations include [GodComplex](https://github.com/The-Running-Dev/SubZeroDev.GameEngine/pull/593), [SkyNetHR](https://github.com/The-Running-Dev/SubZeroDev.SkyNetHR/pull/536), [Data.Json](https://github.com/The-Running-Dev/SubZeroDev.Data.Json/pull/121), [Game of Life](https://github.com/The-Running-Dev/SubZeroDev.GameOfLife/pull/148), and the new [Architecture](https://github.com/The-Running-Dev/SubZeroDev.Architecture/pull/1) documentation repository.

### AgentKit

AgentKit completed its runtime migration to Node 22.18 or newer. Installation, upgrades, safety commands, the `/next` loop, host integration, and session measurement no longer require PowerShell. Repository files are now created on first use, `/sync` updates only the machine-wide checkout, and `.claude/kit.json` plus the copied per-repository command machinery were retired. Seventeen AgentKit pull requests merged; the significant result is less kit in every repository, not seventeen exciting ways to delete it.

### GodComplex — Consequences

The engine acquired its product name and broader interactive-engine positioning while keeping repository, package, and domain compatibility intact. More importantly, campaign composition and content epochs landed.

- Campaigns can include other campaigns as validated, prefixed modules.
- A running host can publish new content without restarting, while existing states continue to resolve the exact campaign version they name.
- Sessions can adopt compatible content; saves, branches, and the replay oracle preserve and cross those epoch changes.
- Eight reproduced review defects were closed, including hidden-result filtering, durable-save ordering, session revision handling, kind/state validation, bounded caches, and package licensing.

That sequence ended with [replay across content epochs](https://github.com/The-Running-Dev/SubZeroDev.GameEngine/pull/594), verified in the PR against 2,345 tests.

### Platform And GitService

Platform shipped an optional OpenID Connect sign-in module, a permission-provider harness, and slices covering authorization failure semantics, tenant isolation, audit guarantees, retention, optimistic concurrency, module lifecycle and seeding, local migrations, mirrored-role expiry, streamed responses, hierarchical settings, and identity linking. The repository merged 44 PRs. Some were documentation. Most were the price of making the documentation true.

GitService merged 21 PRs. The watcher now has a real-repository proof; recovery-code use forces re-enrolment; connected agents hear about tool changes; approvals identify their operator; corrupt clones are quarantined rather than destroyed; wait deadlines use a monotonic clock; live sessions are counted; journals are required by type at both dispatch and host boundaries; registry tables are generated from tool declarations; HTTP JSON handling is centralized; and all 246 source-to-design citations are build-checked.

### Desktop And Machine Setup

- HotCorners shipped `1.0.0-preview.2` with automatic foreground-app profile switching and stronger accidental-activation protection around native window controls, including mixed-DPI regression coverage. The release PR recorded 498 passing tests.
- Setup-Windows automated Dropbox installation and linking while placing ignore rules before the client can merge into `CloudRoot`. The workflow preserves an existing root, survives interruption, and restores it on timeout. Its 34 focused tests and 421-test full suite passed; a real-client run is still outstanding.

## Meaningful Progress

### Cleaner

The new Windows cleaner moved from empty repository to a thirteen-slice implementation: elevation, temp inspection and cleanup, component-store servicing, install/update/uninstall, Windows Update leftovers, drive-use analysis, reviewable junk candidates, registry backup/restore, licence state, everyday file categories, and dead uninstall/App Paths/shared-file-counter detection. The design was reconciled with zero findings. No release was evidenced this week, so this remains implemented rather than declared generally available.

### SkyNetHR And BuildAgent

SkyNetHR removed several Windows and load-sensitive failure modes: rename-over operations are retried through one guarded path, timing tests wait on events instead of hopeful sleeps, and the remaining bounds are recorded. It also added ignored-path-safe rollback, token-budget warnings, and live pending-permission counts in the session UI.

Docker-BuildAgent hardened build classification, production-mode handling, upgrade reproduction, interruption recovery, action pinning, image scanning, and least-privilege tokens. Its global tool is now a packable `BuildAgent.Tool` package with the `build-agent` command and its own-tag release path.

## Decisions

- AgentKit is machine-wide, Node-native, and creates repository-owned files only when a command first needs them. A release no longer rewrites every repository to announce itself.
- GodComplex state resolves content by `(campaignId, campaignVersion)`. New content may be published live, but changing content under an existing version is refused rather than explained later.
- Platform treats an unavailable or stale mirrored permission source as unavailable, not as a denial. Mirrored roles default to a 15-minute maximum age, bounded to 30 seconds through one day.
- GitService explicitly limits its single-instance storage claim to one kernel and mount. Network-share locking is unsupported rather than spiritually supported.

## Open Items

- GodComplex still has an open case where a failed persistence write can leave the in-memory session ahead of durable state ([#580](https://github.com/The-Running-Dev/SubZeroDev.GameEngine/issues/580)).
- Platform's audit table still accepts a direct schema-level `UPDATE` ([#306](https://github.com/The-Running-Dev/SubZeroDev.Platform/issues/306)).
- SkyNetHR still lacks a message-route proof for continuing a session beyond its token budget ([#533](https://github.com/The-Running-Dev/SubZeroDev.SkyNetHR/issues/533)).
- AgentKit retains open work around immutable stash evidence, plugin-container ownership across rollback, and whether design reconciliation belongs at plan end or continuously ([#446](https://github.com/The-Running-Dev/SubZeroDev.AgentKit/issues/446), [#450](https://github.com/The-Running-Dev/SubZeroDev.AgentKit/issues/450), [#460](https://github.com/The-Running-Dev/SubZeroDev.AgentKit/issues/460)).
- Setup-Windows' Dropbox path is covered by tests but was not yet exercised against a real signed-in client in the merged PR.
